# GitHub 与 Gitee 全流程验证清单

自动化测试已覆盖本地仓库的「初始化 → 提交 → 推送 → 拉取」全流程与 `http.proxy` 回归；真实平台的 HTTPS + 个人令牌（PAT）验证需要你的账号，请按下表逐项执行并勾选。

## 前置条件

-   已安装 Git 2.29+，并按[认证说明](../Authentication.zh.md)配置系统凭据助手。
-   在 GitHub 与 Gitee 各准备一个**空的私有仓库**和一枚 PAT（权限包含仓库读写）。

## 每个平台各执行一遍

1. 新建空 Vault，安装并启用插件。
2. 命令面板执行「初始化新仓库」，确认生成初始提交。
3. 命令面板执行「编辑远端」：名称 `origin`，URL 为仓库 HTTPS 地址。
4. 在终端对该仓库执行一次 `git push` 或 `git pull`，让系统凭据助手记录 PAT（插件不保存任何密码）。
5. 写一个笔记，执行「同步」：预期中文通知「已提交 1 个文件」「已推送 1 个文件到远端」。
6. 在网页端确认新提交已出现。
7. 换个目录（或另一台设备）执行「克隆现有远端仓库」，打开后应看到最新笔记。
8. 在网页端修改并提交，回到本机执行「拉取」：预期「已从远端拉取 N 个文件」。
9. 冲突演练：两台设备修改同一文件并分别推送，本机执行「同步」：预期状态栏出现「有冲突」、中文通知；执行「中止冲突中的同步」应能回到同步前状态。
10. 观察状态栏的领先 / 落后与未推送数随操作正确更新。

## http.proxy 回归

插件不应读写 git 自身的 `http.proxy` 配置。自动化测试已覆盖本地场景；如走代理，请确认代理由 git 配置或系统环境提供，插件保持不动。

## 结果记录

-   [ ] GitHub：初始化 → 提交 → 推送 → 拉取全流程通过
-   [ ] Gitee：初始化 → 提交 → 推送 → 拉取全流程通过

-   [ ] `http.proxy` 配置未被插件破坏
