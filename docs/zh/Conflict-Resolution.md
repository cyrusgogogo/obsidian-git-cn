# 解决同步冲突

发生冲突时，插件暂停自动提交、拉取和推送。请勿强制推送或直接丢弃工作区；拉取前生成的保护性提交仍可用于恢复本地修改。

## 合并冲突

1. 打开「源码控制」中的「冲突」分区，逐个打开冲突文件。
2. 在编辑器冲突块中选择「保留本地内容」「保留传入内容」「保留双方内容」，或手动编辑并删除冲突标记。
3. 确认结果符合预期后，点击文件旁的加号，将其标记为已解决。冲突计数为零只表示文本冲突消失，不代表合并已结束。
4. 所有文件解决后，输入提交信息，执行「完成合并」或提交已暂存改动。合并提交成功后才能推送和恢复自动任务。

## 变基冲突

变基与合并不同，不要使用普通提交按钮结束变基。

1. 逐个解决并暂存冲突文件。变基时，Git 的 ours 是变基目标分支，theirs 是正在重放的提交；不要仅凭「本地/传入」标签选择内容。
2. 在该仓库的终端执行 `git rebase --continue`。
3. 后续提交仍可能冲突，重复解决、暂存、继续，直到变基完全结束。
4. 不想继续时，执行插件的「中止冲突并恢复」命令，或在终端执行 `git rebase --abort`。保护性提交仍保留。

## 其他安全限制

- 子模块自动同步暂时禁用；检测到子模块时插件会拒绝同步，请在终端单独处理。
- 限制文件操作到笔记库时，库外未提交改动会阻止拉取。请先备份并处理这些改动，再重试。
- reset 策略使用 `--keep`，更新不覆盖本地改动的受跟踪文件并备份旧历史；不是丢弃改动的硬重置。
- 差异编辑器提示保存被阻止时，先复制未保存的编辑，再重新打开差异。不要直接覆盖同步后的内容。

认证和一般故障参见[认证说明](../Authentication.zh.md)及[常见问题](Common-Issues.md)。
