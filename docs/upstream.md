## 定制改动隔离原则

- 中文文案集中到 `src/i18n.ts` 与后续翻译文件，源码保留英文 key；
- `manifest.json` / `package.json` 中 fork 专属字段（id、名称、描述）单独维护；
- 尽量少改上游文件的无关行，降低每次 merge 的冲突面。

## 跟进命令

```bash
git fetch upstream
git merge upstream/master
```

## 保留的定制与安全限制

- 默认中文、英文 key、中英切换、独立插件 ID `obsidian-git-cn`、版本线 `1.0.0` 与中文帮助入口不变。
- 保留启动拉取、定时拉取/推送、防抖提交、提交后推送、离线自然重试和冲突暂停；拉取前继续生成保护性提交。
- 新增设置、冲突界面、历史文件、差异编辑器、认证提示和错误全部接入词典；回归测试扫描静态翻译键与占位符。
- 设置上游仅写本地跟踪配置，不隐式推送。拒绝 force/delete/mirror 推送配置，原生命令入口仅允许受限命令。
- squash 仅限推送目标是本地祖先的未推送历史；保留备份引用和索引，失败回滚。reset 使用 `--keep`，保留 `refs/obsidian-git/pre-reset/<旧 HEAD>`，会更新无冲突的受跟踪文件而非保持工作区不变。
- 暂不自动更新子模块；检测到本地或待整合远端子模块时拒绝拉取/推送。开启笔记库范围限制且库外有未提交改动时也拒绝同步，避免保护性提交越界。请在终端自行处理这些仓库。
- 变基冲突不允许普通提交完成；解决并暂存后在终端执行 `git rebase --continue`，或用插件中止恢复/`git rebase --abort`。仅在 merge/rebase 真正结束后恢复自动任务。
- 差异编辑器保存进入 Git 队列并校验磁盘基线；外部修改导致基线不匹配时拒绝覆盖，保留未保存编辑供复制。
- 底层 Git debug 输出关闭；错误与日志脱敏仓库路径、URL 查询凭据及认证字段，调试信息只导出布尔/数值设置。
- 本地备份分支：`backup/pre-upstream-20261015`。本次仅合并源码，不创建发布 tag、不推送远端。
