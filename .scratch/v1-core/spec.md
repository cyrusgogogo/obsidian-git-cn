# v1-core 需求规格

> 状态：已确认（2026-08-13）。术语定义见 [CONTEXT.md](../../CONTEXT.md)，架构决策见 [docs/adr/](../../docs/adr/)。

## 背景与目标

本项目是 [Vinzent03/obsidian-git](https://github.com/Vinzent03/obsidian-git)（MIT）的 fork。目标是让中文用户以最小配置，把 Obsidian 笔记库（Vault）自动同步到 Git 远端，界面与文档完整中文化。

## 范围

### 在范围内（v1.0）

- 桌面端：Windows / macOS / Linux。
- 单仓库：一个 Vault 对应一个 Git 仓库。
- 远端：任意标准 Git URL，重点验证 GitHub 与 Gitee；认证走 HTTPS + 个人令牌（PAT）。
- 四种触发：手动、定时、启动时拉取、提交后推送。
- 拉取策略：merge（默认）/ rebase / reset。
- 中文化：默认中文、可切换英文。

### 明确不做（v1.0）

- 移动端（上游实验性、依赖系统 git、不支持 SSH）。
- 子模块 / 多仓库管理。
- SSH 认证（列入二期）。
- 「离开时同步」触发（Obsidian 无可靠的离开仓库事件）。
- 冲突的自动解决（只提示，并提供完整回滚）。

## 功能需求

FR-1 仓库准备
- Vault 尚不是 Git 仓库时，可初始化并创建初始提交。
- 支持配置远端 URL；插件不保存任何密码，认证交给系统 Git 凭据助手。

FR-2 手动同步
- 命令面板提供「同步」命令：拉取 → 合并 → 提交 → 推送，过程状态可见。

FR-3 定时同步
- 可配置间隔，开启后默认每 30 分钟执行一次；0 表示关闭。

FR-4 启动时拉取
- Obsidian 启动后自动拉取远端更新，默认开启，可关闭。

FR-5 提交后自动推送
- 本地自动提交成功后立即推送，默认开启，可关闭。

FR-6 自动提交（防抖）
- 停止编辑默认 5 分钟后自动提交；间隔可配置，0 表示关闭。
- 默认提交信息模板：「同步：YYYY-MM-DD HH:mm」，模板可自定义。

FR-7 拉取策略
- merge（默认）/ rebase / reset 三选一。
- stash 仅作为「拉取前暂存未提交改动」的独立保护开关，不列为拉取策略。

FR-8 保护性提交
- 拉取 / 合并 / 变基前若存在未提交改动，先自动生成保护性提交；失败时该提交留在历史中，可完整回滚。

FR-9 冲突处理
- 冲突时暂停自动同步；中文通知 + 状态栏标记「有冲突」；提供「打开冲突文件」命令；不得静默覆盖或丢弃本地修改。

FR-10 远端变更检测
- 定时 fetch；状态栏常驻显示 ahead / behind；检测到分叉或落后时中文通知。

FR-11 离线与失败处理
- push 失败仅通知，不自动重试；状态栏显示「未推送 N 个提交」；下次触发自然重试。
- 网络与认证错误信息不得包含 Token、密码或私有仓库地址细节。

FR-12 中文化（i18n）
- 源码保留英文 key，运行时默认渲染中文；设置提供「中文 / 英文」切换。
- 设置面板、命令、通知、帮助文档完整中文化。

FR-13 设置面板
- 分类组织：仓库与远端、同步触发、拉取策略、提交、通知。
- 各开关与间隔的默认值如上。

## 非功能需求

- 数据安全：任何可能覆盖本地内容的操作前必须可完整回滚；禁止 force push、删除远端分支、丢弃工作区修改；凭据不得写入日志、通知或提交历史。
- 兼容性：`minAppVersion` 以导入上游时其 manifest 的取值为准。
- 稳定性：冲突与离线是常态场景，必须有明确、可验证的恢复路径。

## v1.0 验收标准

1. 桌面端安装即用：可新建或关联 Vault 的 Git 仓库并绑定远端。
2. 四种触发独立开关，默认值如上。
3. 自动提交、保护性提交、三种拉取策略可配置。
4. 冲突有通知、状态栏标记与「打开冲突文件」入口，且能完整回滚。
5. GitHub 与 Gitee 全流程（HTTPS + PAT）验证通过。
6. 界面与文档完整中文化（中文默认、可切英文）。
7. 无凭据落盘、无 force push 等破坏性操作。
